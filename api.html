A conceptual input assembled from ordered components.

class scenarioflow.series.SeriesSpec(name: str, dt_target: str | None = None, stitcher: ~typing.Dict[str, ~typing.Any] = <factory>, components: ~typing.List[~scenarioflow.component.Component] = <factory>)[source]

Definition of one conceptual input (e.g. a river flow).

Data components run first in listed order, then function components in listed order. Each output is published in the workspace as both <component> and <series>.<component>. Outputs are then stitched in listed order using each component’s effective time.

A single component of a conceptual input.

class scenarioflow.component.Component(name: str, type: str, effective: str | None = None, load_method: ~typing.Dict[str, ~typing.Any] | None = None, method: str | None = None, transformations: ~typing.List[~typing.Dict[str, ~typing.Any]] = <factory>, args: ~typing.Dict[str, ~typing.Any] = <factory>)[source]

One ordered piece of a series.

A data component reads with a named reader (load_method) and applies named transforms in order. A function component calls a named function (method) with args, which usually refer to earlier components via $!{...}.

Load a scenario configuration without resolving OmegaConf interpolation.

Parameters:

path_or_dict (str or dict) – YAML file path, or an already-loaded dict (returned unchanged).

Returns:

Plain-container configuration.

Return type:

dict

Substitution of ${...} parameters and $!{...} workspace expressions.

${name}

A parameter from the define: block or, failing that, an environment variable. Always produces text.

$!{expr}

An expression evaluated against the scenario workspace, e.g. $!{forecast.last_valid_index()}. When the whole string is a single $!{...} the evaluated object is returned; otherwise its text is inlined. Evaluation uses eval() with no builtins and the names in _ALLOWED_FUNCS plus the workspace.

Stitching of ordered component outputs into one series.

Plot scenario series, or open the interactive Assembly Preview mock.

scenarioflow.plot_scenario.plot_scenario(config, series=None, output=None, show=False, gui=False)[source]

Run a scenario and plot its components and assembled series.

Steps:

  1. Load the scenario YAML and run every series.

  2. Select the requested series (default: all).

  3. With gui, open one interactive Assembly Preview per series and block until closed. Otherwise draw one static figure per series, saving to output and/or showing it.

Parameters:

  • config (str or pathlib.Path) – Scenario YAML.

  • series (list of str, optional) – Series names to plot. Unknown names are logged and skipped.

  • output (str or pathlib.Path, optional) – Output file (single series), file stem with image suffix (one file per series, <stem>_<series><suffix>) or directory (<series>.png).

  • show (bool) – Show each static figure interactively.

  • gui (bool) – Open the interactive Assembly Preview mock instead of static plots.
